# 1. THE CURRENT TRUSTSCORE MISSION

TrustScore is:

> **An identity and trust infrastructure platform that turns government-verified identity into reusable trust.**

The strategic foundation is:

```text
NIN / NINAuth
       ↓
Government-backed identity
       ↓
Trust Identity
       ↓
Evidence
       ↓
Reputation / Risk / Resolution
       ↓
Trust Decision
       ↓
Trust Passport / Safety Check / B2B API
```

TrustScore is NOT:

* another generic KYC provider;
* a raw NIN lookup website;
* a public blacklist;
* a credit bureau;
* a bank-data aggregator;
* a universal “good person/bad person” score.

# 8. PARTICULAR NINAUTH SECURITY REQUIREMENTS

The current NINAuth documentation states that normal web integrations should use the SDK, while the backend handles the client secret and authorization-code exchange. Its current API reference documents `POST /api/v1/oauth/token`, PKCE, server-side token handling, ID-token validation and actual granted-scope handling.

Therefore enforce:

```text
CLIENT SECRET
→ backend only

PKCE VERIFIER
→ never exposed to provider authorization URL

STATE
→ cryptographically random
→ server-side transaction binding

AUTHORIZATION CODE
→ one-time
→ short-lived

ID TOKEN
→ server-side validation
→ never merely decoded

GRANTED SCOPE
→ authoritative
→ do not assume requested scope was granted

REFRESH TOKEN
→ backend-only encrypted storage when required
```

Do not implement a fake production flow simply because the mock already works.
