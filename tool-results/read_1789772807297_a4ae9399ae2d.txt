   109→// AUTH batch — unified authentication identifier registry. One UserAccount may
   110→// hold several identifiers; ALL login methods resolve through this table:
   111→//
   112→//   UserAccount ── AuthIdentifier[USERNAME, EMAIL, PHONE, GOOGLE]
   113→//
   114→// value discipline per type:
   115→//   USERNAME — normalized lowercase handle (3–24, [a-z0-9_], reserved-list)
   116→//   EMAIL    — normalized lowercase email
   117→//   PHONE    — phoneFingerprint() = peppered sha256 of E.164 (raw phone NEVER
   118→//              persisted; masked hint only — never in URLs/logs/analytics)
   119→//   GOOGLE   — the provider's stable subject ("sub"), never the raw profile
   120→//
   121→// verified gates linking/recovery (not password login itself — the password
   122→// is the auth factor there). @@unique([type, value]) is the conflict detector.
   123→

   134→  linkedAt    DateTime  @default(now())

   476→// ---------------------------------------------------------------------------
   477→// Stage 5 — TrustScore snapshots (directive §35/§36 score contract).
   478→// Formula: Identity Assurance + Verified Reputation + Verified Credentials +
   479→// Resolution History − Confirmed Risk. Output: score, confidence, risk band,
   480→// human-readable explanation (NDPA §37 automated-decision transparency) and
   481→// freshness. Snapshots are immutable; a new row is written on material change
   482→// or TTL expiry (24h), and only the last 20 per user are retained.
   483→// Stage 8 adds the lifecycle: state (ACTIVE/STALE/FROZEN/RETIRED) + the
   484→// policy that produced the snapshot (every score stays explainable) +
   485→// freeze fields (appeal filed → frozen, appeal decided → recomputed).
   486→// ---------------------------------------------------------------------------
   487→
   488→model TrustScoreSnapshot {
   489→  id          String   @id @default(cuid())
   490→  userId      String
   491→  version     Int      @default(1)
   492→  status      String // NEW | VERIFIED | ESTABLISHED | CAUTION | HIGH_RISK | REVIEW_REQUIRED
   493→  score       Int // 0–100
   494→  confidence  Int // 0–100
   495→  riskBand    String // LOW | MEDIUM | HIGH
   496→  components  String // JSON: per-component {value, max, note}
   497→  explanation String // JSON array of human-readable lines (NDPA §37)
   498→  inputsHash  String // canonical hash of score inputs (change detection)
   499→  trigger     String // INITIAL | MATERIAL_CHANGE | PERIODIC

  1153→// Batch 2 (G8) — Business profile (directive §53: "business identity by RC
  1154→// number — model now, integrate on the provider contract later").
  1155→//
  1156→// HONESTY CONTRACT (the whole point of this model):
  1157→//   - status is UNVERIFIED and STAYS UNVERIFIED until a CAC-class business
  1158→//     verification provider exists. Nothing on this row is a trust signal.
  1159→//   - No score, no band, no trust claims are attached — ever (enforced by
  1160→//     the test matrix invariant: responses expose status only).
  1161→//   - The RC number itself is NEVER persisted raw: a peppered fingerprint
  1162→//     (SIGNAL_PEPPER — same discipline as phone fingerprints) + a masked
  1163→//     display hint. Future business lookups by RC resolve via the
  1164→//     fingerprint (exact-match on the normalized form).
  1165→//
  1166→// Cross-account duplicates of the same RC are ALLOWED at this stage: with
  1167→// no provider there is no adjudication mechanism, and a global unique
  1168→// constraint would let anyone squat unverified RC labels — a claim with
  1169→// zero verification behind it. When the provider lands, verification
  1170→// becomes the scarce, adjudicated resource (and VERIFIED rows get their
  1171→// uniqueness there). Unique per OWNER prevents accidental double-claims.
  1172→model BusinessAccount {
  1173→  id            String   @id @default(cuid())
  1174→  ownerId       String
  1175→  name          String // display name as entered by the owner (rectifiable)
  1176→  rcFingerprint String // peppered sha256 of the normalized RC/BN/IT number — raw never stored
  1177→  rcHint        String // masked display hint, e.g. "RC 123•••" — non-reconstructable
  1178→  status        String   @default("UNVERIFIED") // UNVERIFIED — the only reachable state in this batch
  1179→  createdAt     DateTime @default(now())
  1180→  updatedAt     DateTime @updatedAt
  1181→
  1182→  owner UserAccount @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  1183→
  1184→  @@unique([ownerId, rcFingerprint])
  1185→  @@index([rcFingerprint])
  1186→  @@index([ownerId])
  1187→}
